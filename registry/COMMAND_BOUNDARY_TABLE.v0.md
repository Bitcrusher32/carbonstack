# CarbonStack command boundary table v0

Status: provisional release-boundary artifact
Checkpoint: v0.5.67
Source registry: `registry/commands.v0.yaml`

## Purpose

This table classifies known CarbonStack command, runner-profile, script, sidecar, API, and helper surfaces so release notes and README surfaces do not overclaim them.

This is not an end-user manual. Registry presence is not command promotion. Dev/manual/legacy/internal/future rows are included to prevent command loss and claim drift.

Flag coverage is hybrid and intentionally partial: this table renders `required_flags`, `optional_flags`, and `environment` metadata where the registry has it. Missing flag metadata means the registry still needs enrichment; it does not mean the command has no flags.

## Future lookup-helper direction

A future command/helper lookup can read the registry and this table shape to answer per-command or per-flag questions. Do not build that helper until the table format stabilizes.

Potential future shapes:

    registry command <id>
    registry command --command '<literal command>'
    registry flags <id>

Any future lookup helper must preserve nonclaims and release-boundary classifications.
