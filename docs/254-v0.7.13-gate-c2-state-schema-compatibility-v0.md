# Gate C2 State Schema Compatibility

Status: accepted implementation document  
Scope: v0.7.x Gate C2  
Command: `state-schema-compat-dev`  
Profile: `state-schema-compat-dev`

## Summary

Gate C2 introduces a read-only schema/version compatibility classifier and refusal surface for Comms-owned JSON artifacts.

C2 does not migrate, repair, relocate, or delete state. It creates an explicit compatibility gate that can classify supported, missing, invalid, unsupported, and legacy/unversioned state before later subgates wire deeper path policy and runtime reader enforcement.

## Command

`state-schema-compat-dev`

Important flags:

- `--kind`
- `--path`
- `--output`
- `--allow-refusal-exit-zero`

Supported `--kind` values:

- `state-substrate-inventory`
- `keypackage-receipt`
- `welcome-receipt`
- `workflow-report`
- `cypher-mls-mismatch-report`
- `path-policy-report`
- `write-policy-report`
- `comms-state`

## Supported schema versions

- `carbonstack-state-substrate-inventory/v0`
- `carbonstack-keypackage-consume-receipt/v0`
- `carbonstack-welcome-consume-receipt/v0`
- `carbonstack-workflow-relay-onboarding-report/v0`
- `carbonstack-cypher-mls-mismatch-report/v0`
- `carbonstack-state-path-policy-report/v0`
- `carbonstack-state-write-policy-report/v0`

Current local Comms state is classified as legacy/unversioned rather than migrated.

## Refusal policy

C2 refuses:

- missing path;
- directory instead of JSON file;
- unreadable JSON;
- invalid JSON;
- missing schema on safety-sensitive receipt/report artifacts;
- invalid schema field;
- unsupported schema version.

C2 classifies legacy Comms state without migration.

## Nonclaims

C2 does not claim:

- migration;
- repair;
- state relocation;
- runtime aggregate;
- vault security;
- backup/restore safety;
- trust promotion;
- verified identity;
- Cypher/MLS reconciliation;
- deployment readiness;
- production E2EE;
- Gate D.
