# Gate B5d KeyPackage Consume / Local Receipt / ACK-after-Persist

Status: accepted implementation document  
Scope: v0.7.x Gate B5d  
Command: `openmls-relay-keypackage-consume-dev`

## Summary

B5d implements deterministic delivery consumption of one queued Relay Space KeyPackage envelope.

The command fetches the recipient device's scoped Relay Space inbox, selects exactly one KeyPackage envelope by `envelope_id`, writes the decoded KeyPackage artifact to a local receipt root, persists a receipt manifest, and only then sends the scoped ACK.

## Boundary

B5d is local delivery consume and receipt only.

It is not:

- OpenMLS add-member;
- Welcome generation;
- Welcome join;
- trust or candidate mutation;
- verified identity;
- public KeyPackage directory behavior;
- production key distribution;
- B6.

## Receipt authority

The receipt manifest is local Comms state. It records:

- envelope ID;
- Relay Space ID;
- sender and recipient device IDs;
- content type and protocol version;
- delivery state before ACK;
- payload and artifact metadata;
- receipt paths;
- consume and ACK timestamps;
- explicit nonclaims.

Cypher remains only delivery/ACK authority. Cypher does not verify OpenMLS consume state.

## ACK-after-persist invariant

The command must persist both the artifact and receipt manifest before calling scoped ACK.

If ACK fails after local persistence, the unacked receipt remains and a later replay can retry ACK after validating the receipt identity.

## Idempotence

Exact replay after a successful receipt returns `already_consumed` from the local receipt and does not duplicate the artifact or requeue material.

## Validation

`keypackage-consume-dev` proves:

- artifact and receipt manifest exist before ACK;
- exact replay is stable;
- ACK failure leaves a persisted unacked receipt;
- no add-member, Welcome, trust/candidate, or public directory mutation occurs.
