# v0.5.60 Go toolchain portability decision

Status: docs + module-floor restoration checkpoint
Phase: v0.5.60-REFACTOR
Scope: Go module version truth before future v0.6.0 package rehearsal
Date: 2026-06-09 local session

## 1. Purpose

v0.5.60 records the Go toolchain portability recon and final decision after the REFACTOR cleanup arc.

The starting concern was that `carbonstack-comms` and `carbonstack-cypher` declared:

    go 1.26.3

while runner doctor reported the local launcher as:

    go version go1.24.4 linux/amd64

The question was whether `go 1.26.3` was accidental/unnecessary drift.

## 2. Recon findings

The current dependency graph includes:

    modernc.org/sqlite v1.50.1

That dependency requires:

    go >= 1.25.0

An attempted module-floor reduction to `go 1.24` failed validation because the SQLite dependency requires Go 1.25 or newer.

An attempted module-floor reduction to `go 1.25` also failed validation because the Go toolchain reported that `go.mod` updates were needed and asked for `go mod tidy`.

This means reducing the module floor is no longer a harmless documentation cleanup. It introduces dependency/toolchain churn and should not block the current refactor arc.

## 3. Decision

Restore and keep the component module declarations at:

    go 1.26.3

for:

    carbonstack-comms/go.mod
    carbonstack-cypher/go.mod

Keep the runner module at:

    carbonstack/tools/carbonstack-validate/go.mod -> go 1.24

because the runner itself remains separate and currently validates under the local Go 1.24 launcher.

## 4. Current correct wording

Correct current wording:

    The runner doctor may report the local launcher as Go 1.24.4.
    Current Comms/Cypher modules declare Go 1.26.3.
    Current Comms/Cypher dependency graph cannot be lowered to Go 1.24 because modernc.org/sqlite requires Go >= 1.25.
    A Go 1.25 reduction caused go.mod/tidy churn and was not adopted.
    For current package rehearsal, use a Go toolchain setup capable of satisfying the component module declarations.

## 5. Blunder / recovery note

The attempted lowering from 1.26.3 to 1.24 and then 1.25 was over-optimization.

The useful result was discovering that the real risk is not simply stale documentation; it is toolchain dependency behavior.

The recovery is to restore the previously validating `go 1.26.3` component floor and preserve this recon as a decision record rather than forcing a minimum-floor reduction now.

## 6. Validation expectation

After restoration, validate:

    carbonstack-comms: go test ./... -count=1
    carbonstack-cypher: go test ./... -count=1
    carbonstack/tools/carbonstack-validate: go test ./... -count=1
    carbonstack/tools/carbonstack-validate: go run . --profile doctor
