# Gate C3 Closure

Status: accepted closure document  
Scope: v0.7.x Gate C3

## Closed behavior

Gate C3 is closed when:

- `state-path-policy-dev` exists;
- `state-path-policy-dev` profile passes;
- the report schema `carbonstack-state-path-policy-report/v0` is emitted;
- explicit `--state` compatibility is preserved;
- canonical `.carbonstack-comms` root is documented as preferred but not mandatory;
- explicit `--state-root` mismatches are classified rather than refused;
- parent traversal is refused;
- sidecar/Cypher/evidence roots are classified only;
- command reference and registry metadata remain current;
- missing nonclaims remain zero.

## What C3 prepares

C3 prepares C4 by separating path policy from atomic write, lock, partial-state, and replay behavior.

C4 should build on the path classes defined here rather than rediscovering path ownership ad hoc.

## What C3 does not do

C3 does not migrate, repair, relocate, delete, or clean state. It does not wire every runtime command into a final path-policy gate yet. Later Gate C subgates may adopt the C3 classifier into individual writer paths after C4 atomicity boundaries are stable.
