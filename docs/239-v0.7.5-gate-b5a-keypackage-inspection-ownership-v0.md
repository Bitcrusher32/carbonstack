# Gate B5a KeyPackage Inspection, Identity, Lifetime, and Ownership

Status: accepted implementation contract for Gate B5a  
Checkpoint: v0.7.5 development line  
Scope: material KeyPackage lifecycle foundation

## Purpose

Gate B5a establishes a read-only material KeyPackage inspection surface before
repeatable generation, rotation, Relay publication, deterministic consumption,
or Welcome lifecycle work.

The authoritative KeyPackage lifecycle identity is the validated OpenMLS
`key_package_ref`.

The serialized artifact SHA-256 is transport-integrity metadata. It is not a
replacement identity for the KeyPackage.

## Surfaces

Internal sidecar command:

    cargo run -- keypackage-inspect \
      --device-label <local-sidecar-label> \
      --keypackage <serialized-keypackage-path>

Comms dev wrapper:

    go run ./cmd/comms openmls-keypackage-inspect-dev \
      --sidecar-device-label <local-sidecar-label> \
      --keypackage <serialized-keypackage-path>

Permanent validation profile:

    cd carbonstack/tools/carbonstack-validate
    go run . --profile keypackage-inspect-dev \
      --root /path/to/carbonstack_umbrella \
      --clean-generated

## Inspection contract

Successful inspection proves all of the following for the supplied artifact:

- TLS deserialization consumes the complete artifact with no trailing data.
- OpenMLS KeyPackage validation succeeds for the supported protocol version.
- the OpenMLS KeyPackage reference can be recomputed;
- lifetime `not_before` and `not_after` metadata is exposed;
- the artifact SHA-256 and size are recomputed;
- the supplied local sidecar device label has a readable public-bundle summary
  and manifest;
- summary and manifest agree with each other and with the validated artifact;
- the inspection performs no state writes.

## Ownership boundary

`owner_match: true` means:

- the local sidecar public-bundle summary names the supplied sidecar label;
- the local sidecar public-bundle manifest names the supplied sidecar label;
- both metadata records match the validated KeyPackage reference;
- both metadata records match the artifact SHA-256 and size.

This is local-origin evidence only.

It does not prove:

- CarbonStack account identity;
- CarbonStack device identity;
- Relay Space membership;
- human identity;
- trust promotion;
- authenticated administration;
- secure enrollment.

Those bindings require later lifecycle work. Relay publication and binding are
deferred to B5c.

## Deterministic refusals

The surface refuses:

- missing required arguments;
- invalid device labels;
- missing or unreadable artifacts;
- malformed TLS artifacts;
- trailing bytes;
- failed OpenMLS validation;
- failed KeyPackage reference calculation;
- invalid lifetime ordering;
- a KeyPackage that is not yet valid;
- a KeyPackage at or after its expiry boundary;
- missing or malformed local public-bundle metadata;
- cross-owner metadata mismatches;
- tampered artifacts.

No refusal mutates sidecar, Comms, trust, candidate, Cypher, or Relay state.

## Gate relationship

B5a closes only the inspection, identity, lifetime, and local-ownership
foundation.

B5b remains responsible for repeatable generation and rotation, including
fresh references, overlap policy, and explicit retirement behavior.

A continuity breakpoint is required immediately after B5b closes, before B5c
Relay publication and duplicate/reuse semantics begin.
