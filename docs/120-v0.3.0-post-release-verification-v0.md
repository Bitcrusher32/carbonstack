## 1. Purpose

This document records the first post-release verification pass after the v0.3.0 experimental backbone release.

The goal is not to add features.

The goal is to verify that the public release package is downloadable, checksum-verifiable, extractable, internally coherent, and free of obvious generated/private/build artifacts.

## 6. Required-file check

The required-file check initially expected:

    carbonstack-comms\go.sum

That file was not present in the extracted `carbonstack-comms` snapshot.

This is a verification finding, not a v0.3.0 release failure, if the source repo also does not contain `go.sum`.

For v0.3.1 verification purposes, `carbonstack-comms\go.sum` should be treated as optional / include-if-present unless Go dependency state later requires it.

Future packaging docs should avoid listing `go.sum` as unconditional critical material for repos that do not contain one.

## 7. LICENSE placement note

The v0.3.0 release page includes a standalone LICENSE asset.

If the source snapshots do not contain LICENSE internally, this is a known v0.3.0 packaging caveat.

Future releases should place LICENSE in each relevant repo before generating release source snapshots.

## 8. What this verification does not prove

A passing release-asset verification does not prove:

    production readiness;
    production E2EE;
    hostile-server safety;
    metadata privacy;
    Android readiness;
    secure vault/storage;
    external audit;
    certification.
