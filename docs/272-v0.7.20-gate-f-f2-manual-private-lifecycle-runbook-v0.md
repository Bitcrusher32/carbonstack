# Gate F F2 Manual Private Lifecycle Runbook

Status: accepted operator runbook
Scope: v0.7.x Gate F F2
Profile: gate-f-operator-docs-runbook-dev

## Purpose

This document describes the current manual-private lifecycle for the v0.7.x operational spine after Gate E closure and Gate F F1 surface classification.

Gate E is closed for the manual-private native deployment model.

Gate F F1 is closed for release/package/runtime surface classification.

Gate F F2 closes operator documentation and runbook authority only.

## Current lifecycle posture

The current lifecycle is a dev/pre-alpha manual-private lifecycle.

It is suitable for project validation and controlled private operator rehearsal. It is not a public deployment model and not a production claim.

No release creation is performed by this runbook.

No package staging execution is performed by this runbook.

No package publication is performed by this runbook.

full-runtime-dev remains reserved until a later package/runtime candidate validates one coherent preferred lifecycle.

## Orientation step

Before any operation, record:

- carbonstack head
- carbonstack-comms head
- carbonstack-cypher head
- carbonstack-os head
- git status for all four repositories
- current evidence root
- current LogDoc and Breakpoint checkpoint

All four repositories must be clean before tracked mutation.

## Manual-private deployment model

The accepted deployment model is a single-host private operator model with explicit paths and explicit environment.

The deployment root should contain:

- bin
- config
- state/comms
- state/cypher
- state/sidecar
- logs
- evidence
- tmp

Cypher must use explicit environment and must not rely on repo-root defaults.

## Normal validation order

Use this conceptual order:

1. Confirm clean repositories.
2. Inspect Cypher config with terminating config inspection.
3. Validate current registry/reference freshness.
4. Use Gate E closure profile if deployment closure proof must be refreshed.
5. Use Gate F F1 profile when release/package/runtime surface classification must be refreshed.
6. Use Gate F F2 profile to validate operator docs/runbook closure.
7. Generate the private LogDoc and Breakpoint after F2.

## Stop conditions

Stop and ask for a new contract if work would require:

- release creation
- release upload
- package publication
- package staging execution
- service or systemd installation
- helper install
- public ingress
- container work
- TUI work
- migration implementation
- destructive cleanup
- verified identity or trust promotion
- vault or backup/restore work
- PQ/hybrid work
- Android work
- CarbonStackOS implementation

## Handoff

After F2 passes, generate the next private Markdown LogDoc and lean JSON Breakpoint before Gate F F3.
