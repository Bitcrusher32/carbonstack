# CarbonStack v0.6.17 Same-State Message Failure Dev Profile v0

Status: implementation checkpoint for first same-state failure-path hardening profile.

## Scope

This document records the committed profile:

    go run . --profile same-state-message-failure-dev --root <umbrella root> --clean-generated

The profile proves one narrow failure rule inside the same-state universe:

    wrong-conversation message-inbox-dev --ack must not ack and must not drain Bob's inbox.

It then proves the message remains recoverable by opening with the correct conversation and explicit `--ack`.

## Why this exists

v0.6.16 added the positive-path profile:

    same-state-integrated-dev

That profile proves:

    Relay onboarding -> Bob joins same conversation -> message-send-dev -> message-inbox-dev --ack

v0.6.17 starts failure hardening without claiming an adversarial harness.

## Sequence

The profile performs:

1. Build a temporary Cypher binary.
2. Start one temporary Cypher server with one temporary DB.
3. Initialize Alice/Bob Comms state files against that server.
4. Create/claim dev invites and register devices.
5. Create one Relay Space and routing members.
6. Create Alice/Bob sidecar identities.
7. Alice creates one conversation.
8. Bob submits KeyPackage.
9. Alice add-member creates Welcome.
10. Bob joins with ACK_AFTER_JOIN enabled.
11. Alice sends a normal message.
12. Bob attempts `message-inbox-dev --ack` with a wrong conversation label.
13. Assert the wrong-conversation attempt reports message-open failure.
14. Assert ack count does not change.
15. Assert Bob inbox count does not change.
16. Assert output does not report `acked: true` or `ack_delivery_state: acknowledged`.
17. Bob opens the same message with the correct conversation.
18. Assert correct open succeeds and acks.
19. Assert Bob inbox is empty after the correct open/ack.

## Expected evidence

Wrong-conversation attempt:

    message open failed
    stage: message_open
    acked: false
    opened_envelopes: 0
    open_failures: 1
    ack_failures: 0

Expected counters:

    acks_after_bad_open == acks_after_join
    bob_inbox_count_after_bad_open == bob_inbox_count_before_bad_open
    acks_after_correct_open == acks_after_join + 1
    bob_inbox_count_after_correct_open == 0

    PQ or hybrid security.

## Relationship to future adversarial harness

This is a failure-path hardening profile, not an adversarial harness.

A later profile or flag may cover broader deterministic adversarial cases such as replay, duplicate, drop, delay, malformed payload, stale Welcome, wrong Relay Space, or wrong recipient.

Do not use this profile alone to claim hostile-server safety.
