# CarbonStack v0.6.21 Same-State Welcome Join Failure Dev Profile v0

Status: implementation checkpoint for fixed Welcome join failure behavior after the v0.6.20 sidecar atomic state-write patch.

## Scope

This document records the committed profile:

    go run . --profile same-state-welcome-join-failure-dev --root <umbrella root> --clean-generated

The profile proves a narrow Relay onboarding failure invariant inside the same-state universe:

    corrupt Welcome join fails;
    corrupt Welcome join does not ack;
    corrupt Welcome join does not drain Bob's Relay inbox;
    corrupt Welcome join leaves no final/staging Bob conversation state;
    restored valid Welcome still joins and acks with the same conversation label.

## Why this exists

v0.6.20 found and fixed a real state-safety bug.

Before the fix:

    corrupt Welcome join did not ack;
    corrupt Welcome join did not drain;
    but failed sidecar conversation-join left final-path Bob conversation state;
    restored valid Welcome then failed with conversation_already_exists.

The Comms sidecar patch changed join materialization to stage and promote joined state only after successful materialization and reloadability evidence.

v0.6.21 locks that fixed behavior into a live-umbrella runner profile.

## Sequence

The profile performs:

1. Build a temporary Cypher binary.
2. Start one temporary Cypher server and DB.
3. Create Alice/Bob Comms state files.
4. Create accounts/devices.
5. Create one Relay Space and two routing members.
6. Create Alice/Bob sidecar identities.
7. Alice creates one conversation.
8. Bob submits KeyPackage to Alice through Relay Space.
9. Alice consumes KeyPackage and sends Welcome to Bob.
10. The queued Welcome payload is corrupted in the temporary Cypher DB.
11. Bob runs `openmls-relay-join-dev --ack-after-join`.
12. Assert the corrupt join fails without join/ack success markers.
13. Assert ack count is unchanged.
14. Assert the Welcome has no ack row.
15. Assert Bob's Relay inbox is not drained.
16. Assert Bob has no final or staging conversation state for that conversation.
17. Assert Bob conversation load-check fails after the corrupt join.
18. Restore the valid Welcome payload.
19. Bob reruns `openmls-relay-join-dev --ack-after-join`.
20. Assert the restored join succeeds.
21. Assert the restored Welcome is acked only after successful join.
22. Assert Bob's Relay inbox drains after the valid join.
23. Assert final Bob conversation state exists.
24. Assert Bob conversation load-check succeeds.

## Expected evidence

Bad join:

    bad_join_rc != 0
    no status: joined
    no joined: true
    no welcome_acked: true
    no ack_delivery_state: acknowledged
    ack count unchanged
    Welcome ack rows unchanged
    Bob Relay inbox count unchanged
    final_state_after_bad_join: absent
    staging_state_after_bad_join: absent

Good join:

    good_join_rc: 0
    status: joined
    joined: true
    welcome_acked: true
    ack_delivery_state: acknowledged
    group_reloadable: true
    Welcome ack rows: 1
    Bob Relay inbox count: 0
    final_state_after_restored_join: present
    restored_join_recovered_without_manual_cleanup: yes
