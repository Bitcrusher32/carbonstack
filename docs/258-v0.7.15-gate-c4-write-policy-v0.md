# Gate C4 Write Policy

Status: accepted implementation document  
Scope: v0.7.x Gate C4  
Command: `state-write-policy-dev`  
Profile: `state-write-policy-dev`

## Summary

Gate C4 introduces a read-only write-policy classification surface for atomic writes, lock discipline, partial-state behavior, replay behavior, and cleanup boundaries.

C4 does not rewrite every runtime writer. It classifies current behavior and future hardening targets.

## Command

`state-write-policy-dev`

- `--state-root`
- `--sidecar-dir`
- `--cypher-db`

- `--output`

## Report schema

`carbonstack-state-write-policy-report/v0`

## Closed classifications

C4 classifies:

- C1/C2/C3 generated reports as atomic generated evidence writers;
- B5d KeyPackage consume receipts as atomic lock-guarded receipt writers with replay classification;
- B6 Welcome consume receipts as atomic lock-guarded receipt writers with ACK-after-join/failed-join partial-state semantics;
- B8 workflow reports as atomic report writers with exact replay classification;
- local Comms state, trust state, and identity-candidate state as direct-write or append surfaces that remain future-hardening warnings;
- sidecar state as sidecar-owned;
- Cypher DB state as Cypher-owned;
- validator/evidence roots as generated/evidence-only.

## Policy

C4 is classify-first.

Direct local state/trust/candidate writes are not silently rewritten in C4. They are flagged as future-hardening warnings so later work can decide whether to add atomic/lock helpers without collapsing Gate C into a broad risky rewrite.

## Nonclaims

C4 does not claim:

- C5 Gate C closure;
- universal runtime writer rewiring;
- migration;
- repair;
- state relocation;
- cleanup implementation;
- destructive cleanup;
- vault security;
- backup/restore safety;
- trust promotion;
- verified identity;
- Cypher/MLS reconciliation;
- deployment readiness;
- full-runtime-dev;
- Gate D runtime aggregate;
- production E2EE;
- Android or CarbonStackOS implementation.
