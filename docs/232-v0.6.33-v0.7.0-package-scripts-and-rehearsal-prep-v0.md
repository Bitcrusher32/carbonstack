## Script strategy

v0.6.0 scripts remain historical prior art.

v0.7.0 uses forked scripts rather than parameterizing v0.6.0 scripts.

Rationale:

- release scripts are release-critical evidence;
- package metadata and runbook text are version-specific;
- fork-first avoids hiding stale release claims behind variables;
- the v0.7.0 scripts can be committed before their output is used as rehearsal evidence.

## Package shape

The v0.7.0 package flow stages tracked HEAD snapshots of:

- `carbonstack`;
- `carbonstack-comms`;
- `carbonstack-cypher`.

It excludes:

- `carbonstack-os`.

`carbonstack-os` remains future constrained-appliance OS work and is not part of the runnable package validation surface.

## Validation shape

Primary validation:

    go run . --profile verify-checksums --root <package-root>
    go run . --profile full-validate-release --root <package-root> --clean-generated

Compatibility validation:

    go run . --profile full --root <package-root> --clean-generated

Current behavior:

    full-validate-release = release-snapshot + local-cypher

`release-snapshot` already calls `core`.
