# CarbonStack v0.6.2 Legacy Stub Demotion

**Status:** pre-alpha / experimental implementation boundary document  
**Generated:** 2026-06-13 20:08:17 UTC  
**Anchor:** v0.6.1 message-surface preflight  
**Purpose:** Require explicit opt-in for the legacy mock/stub `send`, `inbox`, and standalone `ack` CLI surfaces while preserving OpenMLS dev message flow, Relay Space scoped ack behavior, and low-level compatibility history.

---

## 0. Summary

v0.6.2 demotes the old stub-era Comms message commands from default-callable behavior into explicit opt-in behavior.

Gated legacy commands:

    send
    inbox
    ack

Required opt-in flag:

    --allow-legacy-stub

This does not change:

    openmls-send-dev
    openmls-inbox-dev --ack
    Relay Space scoped ack helpers
    Cypher API ack routes
    OpenMLS sidecar message-protect/message-open behavior

---

## 1. Why this change exists

The v0.6.1 preflight chose `openmls-send-dev` and `openmls-inbox-dev --ack` as the current dev/pre-alpha seed for normalized OpenMLS application-message flow.

The older `send`, `inbox`, and standalone `ack` commands remained useful continuity surfaces, but their names were too easy to mistake for the normal message UX. The old `send` and `inbox` path uses the mock/stub provider and text-stub protocol version. `inbox` can print `stub_plaintext`.

v0.6.2 keeps the old path available for explicit compatibility/testing while preventing accidental default use.

---

## 2. Behavior after v0.6.2

Without `--allow-legacy-stub`:

    comms send
    comms inbox
    comms ack

return an explicit opt-in error and print legacy boundary warnings.

With `--allow-legacy-stub`, the old behavior remains available.

Examples:

    go run ./cmd/comms send --allow-legacy-stub --to-device <device-id> --message <text>
    go run ./cmd/comms inbox --allow-legacy-stub
    go run ./cmd/comms ack --allow-legacy-stub --envelope <envelope-id>

---

## 3. Ack boundary

The standalone legacy `ack` CLI is gated because it belongs to the older CLI surface.

This does not gate or change:

    openmls-inbox-dev --ack
    openmls-relay-join-dev --ack-after-join
    internal Relay Space scoped ack helpers
    CarbonStackCypher API ack routes

Acknowledging an envelope remains delivery/local-processing state only. It is not trust, identity verification, hostile-server safety, metadata privacy, or production security proof.

---

## 4. Registry/table impact

The command registry and command boundary table now mark `comms.send`, `comms.inbox`, and `comms.ack` as explicitly opt-in legacy surfaces.

Registry/table updates are intentionally limited to the changed behavior and flags. No OpenMLS dev command is promoted to mature UX by this change.
