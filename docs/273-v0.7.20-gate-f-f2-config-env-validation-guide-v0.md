# Gate F F2 Config Env Validation Guide

Status: accepted operator guide
Scope: v0.7.x Gate F F2

## Purpose

This document records the accepted config and env posture for the manual-private lifecycle.

The core rule is explicit configuration. Do not rely on repo-root defaults for operator deployment.

## Cypher environment

Required explicit values:

- CYPHER_ADDR
- CYPHER_DB
- CYPHER_MIGRATIONS
- CYPHER_DEV_INVITE

CYPHER_ADDR should be loopback for the current manual-private deployment model.

CYPHER_DB should point inside the deployment root, normally under state/cypher.

CYPHER_MIGRATIONS should point to the intended migrations directory.

CYPHER_DEV_INVITE should be explicit for dev/pre-alpha manual-private validation.

## deployment root

The deployment root is an operator-owned tree, not the repository root.

Expected shape:

- bin
- config
- state/comms
- state/cypher
- state/sidecar
- logs
- evidence
- tmp

## cypher config inspection

Cypher config inspection must be terminating.

The accepted inspection surfaces are:

- go run ./cmd/cypher --help
- go run ./cmd/cypher --print-config
- go run ./cmd/cypher --check-config

The config report schema is carbonstack-cypher-config-inspection/v0.

The report must make DB source visible and must not start the server.

## Validation posture

Use config inspection before treating a deployment root as valid.

Use Gate E native deployment validation when start, stop, restart, explicit DB root, and Gate C state policy need mechanical proof.

Use Gate F F2 only for docs/runbook closure, not for runtime proof.

## Nonclaims

This guide does not implement service installation, systemd, public ingress, container deployment, TUI, release packaging, production E2EE, verified identity, trust promotion, vault, backup/restore, PQ/hybrid, Android, or CarbonStackOS.
