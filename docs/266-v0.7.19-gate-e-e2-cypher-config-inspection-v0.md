# Gate E E2 Cypher Config Inspection

Status: accepted implementation document  
Scope: v0.7.x Gate E E2  
Primary surface: `carbonstack-cypher/cmd/cypher`

## Summary

Gate E E2 adds terminating Cypher config-inspection surfaces:

- `--help`
- `--print-config`
- `--check-config`

This directly addresses the Gate E recon finding that `cmd/cypher` behaved only as a blocking server entrypoint and could not be safely inspected with `--help`.

## Closed behavior

`--print-config` prints a JSON report with schema:

carbonstack-cypher-config-inspection/v0

The report records:

- effective address;
- address source;
- DB path;
- DB path source;
- whether the DB path is the repo-relative default `cypher.db`;
- migrations directory;
- migrations source;
- dev-invite enablement without printing the invite value;
- server-entrypoint posture;
- terminating-inspection posture;
- Gate E warning that operator deployment should use explicit env.

`--check-config` validates:

- resolved address is syntactically valid;
- DB path is nonempty;
- DB parent exists and is a directory;
- migrations directory is readable;
- migrations directory contains SQL migrations.

Neither surface starts the server.

## Gate E meaning

E2 does not implement deployment by itself. It removes an operator-inspection hazard before later runbook/helper/service decisions.
