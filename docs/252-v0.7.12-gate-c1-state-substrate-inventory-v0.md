# Gate C1 State Substrate Inventory

Status: accepted implementation document  
Scope: v0.7.x Gate C1  
Command: `state-substrate-inventory-dev`  
Profile: `state-substrate-inventory-dev`

## Summary

Gate C1 introduces the first executable state substrate inventory and authority map.

The command is read-only by default. Optional `--output` writes a generated evidence report, not runtime state.

C1 does not enforce schema compatibility yet, does not migrate state, does not repair state, and does not create a vault, backup/restore system, deployment surface, trust layer, verified identity layer, or runtime aggregate.

## Canonical state-root posture

C1 accepts a canonical Comms-owned state root as a policy anchor, not a brittle mandatory chokepoint.

Accepted behavior:

- `--state` remains supported.
- The default state root derives beside `--state`.
- `--state-root` may explicitly override the Comms-owned inventory root.
- Sidecar state remains sidecar-owned.
- Cypher DB state remains Cypher-owned.
- Evidence roots remain evidence, not runtime authority.
- Legacy, unsupported, or safely broken surfaces are classified rather than deleted or normalized.

## Command

`state-substrate-inventory-dev`

Important flags:

- `--state`
- `--state-root`
- `--sidecar-dir`
- `--cypher-db`
- `--evidence-root`
- `--output`

## Output

The machine-readable report schema is:

`carbonstack-state-substrate-inventory/v0`

The report classifies:

- Comms state root;
- Comms state file;
- trust records;
- trust events;
- identity candidates;
- KeyPackage receipt root and discovered receipts;
- Welcome receipt root and discovered receipts;
- workflow report root and discovered workflow reports;
- sidecar project directory;
- sidecar generated state root;
- optional Cypher DB;
- optional evidence root.

## Nonclaims

C1 does not claim:

- C2 schema enforcement;
- migration;
- repair;
- deletion or cleanup;
- vault security;
- backup/restore safety;
- verified identity;
- trust promotion;
- Cypher/MLS reconciliation;
- deployment readiness;
- full-runtime-dev;
- Gate D runtime aggregate;
- production E2EE.
