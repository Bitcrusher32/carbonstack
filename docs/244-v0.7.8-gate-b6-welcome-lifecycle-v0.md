# Gate B6 Welcome Lifecycle

Status: accepted implementation document  
Scope: v0.7.x Gate B6  
Primary command: `openmls-relay-welcome-consume-dev`  
Profile: `welcome-lifecycle-dev`

## Summary

B6 formalizes the dev/pre-alpha Welcome lifecycle after Gate B5 closure.

B5 closed KeyPackage generation, publication, delivery consumption, and ACK-after-persist. B6 is the next bounded leaf: Welcome delivery consumption, local persistence, sidecar `conversation-join`, and ACK only after durable local join evidence.

## Implemented recipient command

`openmls-relay-welcome-consume-dev`:

1. loads the recipient Comms state;
2. fetches the scoped Relay Space Welcome inbox;
3. selects exactly one Welcome envelope by `envelope_id`;
4. writes the exact Welcome bytes to a local receipt root;
5. persists a receipt manifest before calling OpenMLS;
6. runs sidecar `conversation-join`;
7. persists successful join evidence;
8. ACKs the scoped Welcome envelope only after persisted join evidence;
9. returns stable replay classification from the local receipt.

## Existing sender path preserved

B6 preserves the existing lower-level sender-side surfaces:

- `openmls-relay-add-member-dev`
- `openmls-relay-welcome-submit-dev`

These remain dev/pre-alpha leaves. They do not become identity verification, trust promotion, or production onboarding.

## Nonclaims

B6 does not claim:

- verified identity;
- trust promotion;
- secure enrollment;
- production E2EE;
- public directory safety;
- backup/restore safety;
- hostile-server safety;
- B7 Cypher/MLS reconciliation;
- general user UX.

## Validation

`welcome-lifecycle-dev` proves:

- local Welcome persistence before join;
- ACK-after-join;
- no ACK after failed join;
- existing relay add-member/join positive path still passes;
- B5d remains not-add-member and not-Welcome-lifecycle.
