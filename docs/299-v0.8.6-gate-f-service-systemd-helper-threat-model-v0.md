# Gate F v0.8.x Service / systemd / Helper Threat Model

Status: design-only model  
Gate: F1 Native Deployment / Process Adversarial Contract  

## Rule

This document does not implement service, systemd, helper install, public ingress, or container readiness.

It exists so later service/helper/container work cannot smuggle readiness claims ahead of native/manual-private evidence.

## Model topics

- unit ownership;
- working directory;
- environment/config source;
- DB path;
- state root;
- log path;
- least privilege;
- restart policy;
- failure visibility;
- secret/log hygiene;
- port binding;
- upgrade/restart failure;
- cleanup boundaries;
- operator rollback path;
- why implementation remains blocked.

## Required future service/systemd questions

- Which user owns the process?
- Which directories are writable?
- Are DB/log/state paths explicit and operator-visible?
- Are config/env values printed in safe redacted form?
- Does restart preserve state without silent repair?
- Can a stale process be detected without killing unrelated processes?
- Can cleanup remove only known disposable roots?
- Does failure leave a report rather than a false success?
- Does any helper accidentally create public ingress or privileged install semantics?

## Nonclaims

Not service readiness. Not systemd readiness. Not helper install. Not public ingress. Not container readiness. Not deployment hardening certification. Not production security.
