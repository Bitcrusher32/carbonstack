## 4. Current persistence boundaries

Current persistence is split across:

    Comms local JSON files;
    Comms trust JSON / JSONL files;
    OpenMLS sidecar generated state roots;
    Cypher SQLite database;
    temporary runner/package validation roots.

This is acceptable for dev/pre-alpha work, but it is not yet a coherent production storage architecture.

Current stable observation:

    Cypher server-side persistence is the most validated persistence domain today because local-cypher proves restart behavior against the same temporary SQLite DB.

Current weaker areas:

    Comms local state has simple save/load tests but no migration/versioning policy.
    Trust state has useful tests but no tamper/migration/recovery policy.
    Sidecar provider state is real OpenMLS state but dev-local and not vault-backed.
    Artifact staging has working helpers but no durable lifecycle policy.

## 5. Must-not-silently-regenerate list

These state items must eventually produce loud warnings, errors, or recovery flows if unexpectedly missing/replaced:

    Comms account ID after invite claim;
    Comms device ID after registration;
    Comms public identity key / future real identity binding;
    trust.json device records;
    trust-events.jsonl event history;
    sidecar signer identity material;
    sidecar provider storage;
    OpenMLS conversation/group state;
    group epoch/membership state;
    known device fingerprints;
    revocation records;
    persistent Cypher operator DB migrations/checksums.

Items that may be safely regenerated only under explicit dev/test rules:

    temporary runner roots;
    temporary smoke-test state;
    public bundle artifacts when explicitly requested;
    downloaded relay staging artifacts before final lifecycle rules;
    temporary local-cypher DBs.

## 6. Future vault relevance

The future vault should not be designed as a generic encrypted folder.

It should be designed around state domains:

    identity-bearing state;
    trust-bearing state;
    group/conversation-bearing state;
    message/plaintext state;
    relay-staging state;
    recovery/export state;
    revocation/compromise state.

The current files most likely to become vault-protected or vault-adjacent:

    Comms trust store and event log;
    future real Comms identity state;
    OpenMLS signer/provider storage;
    OpenMLS conversation/group state;
    local message database when implemented;
    backup/export/recovery bundles.

The current files less likely to become vault contents:

    release package checksums;
    runner metadata;
    source docs;
    Cypher server DB, unless running a local single-user appliance mode with a different threat model.

## 7. PQ / ciphersuite migration relevance

PQ/hybrid work must not start as a one-line ciphersuite flip.

State domains affected by PQ/hybrid migration:

    KeyPackage artifact generation and size;
    Welcome artifact compatibility and size;
    OpenMLS group/provider state;
    protocol_version and content_type mapping;
    trust display and safety warnings;
    group reinit/rekey policy;
    runner artifact-size assumptions;
    release claim boundaries.

v0.5.x should preserve this sequence:

    state-domain inventory;
    storage domain model;
    trust-state model;
    PQ/hybrid ciphersuite recon;
    PQ/hybrid lifecycle test;
    migration policy;
    PQ claim-boundary record.

## 8. Immediate implications

1. Current Comms local state is too stub-era to be the final identity model.
2. Current Comms trust state is useful and test-backed, but it is separate from OpenMLS provider identity state.
3. OpenMLS bootstrap wrappers intentionally do not mutate Comms trust state yet.
4. Sidecar provider state is real enough to require serious handling, but not production-secure enough to call a vault.
5. Cypher persistence is validated for local relay lifecycle/restart, but server-side persistence does not solve client vault/state correctness.
6. Artifact staging is the next place where replay/order/ack/lifecycle bugs can creep in.
7. A mature local-backbone profile should remain reserved until state/reset/provider/trust semantics are deliberate.
