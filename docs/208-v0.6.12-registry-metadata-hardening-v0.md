# CarbonStack v0.6.12 Registry Metadata Hardening v0

Status: registry/docs hardening checkpoint
Scope: command-reference readiness metadata
Checkpoint target: v0.6.12
Public release impact: none; current public release remains v0.6.0 State/UX Boundary Validation Pre-Release

## 1. Purpose

v0.6.12 hardens registry metadata so a future generated command reference can be professional and bounded without over-promoting dev/internal/legacy surfaces.

This document records the intended scope and validation expectations for the v0.6.12 registry metadata pass.

## 2. What v0.6.12 changes

v0.6.12 is intended to update:

    registry/commands.v0.yaml
    registry/README.md
    docs/README.md
    tools/carbonstack-validate/README.md
    this document

The hardening pass adds or clarifies metadata for:

    nonclaims;
    validation_surface;
    runner root/cleanup flags where exact and known;
    existing lifecycle_status where appropriate and already in the existing vocabulary;
    internal sidecar command boundaries;
    Cypher API boundaries;
    historical script boundaries.

## 3. What v0.6.12 does not change

v0.6.12 does not:

    generate registry/COMMAND_REFERENCE.v0.md;
    generate Unix man pages;
    replace registry/COMMAND_BOUNDARY_TABLE.v0.md;
    mutate full;
    mutate release-snapshot;
    mutate integrated-runtime-dev;
    add full-runtime-dev;
    add runtime commands;
    change Comms behavior;
    change Cypher behavior;
    change OpenMLS sidecar behavior;
    claim production security.

## 4. Generation blocker being reduced

v0.6.11 deliberately left `registry-lookup --missing-nonclaims` visible as evidence for the next rung.

The v0.6.12 goal is to close the known missing-nonclaims queue and reduce validation-surface opacity for sidecar, Cypher API, and script rows.

This is still not equivalent to generated-reference readiness.

## 5. Source of truth policy retained

Future command reference generation remains deferred.

The intended future source remains:

    registry/commands.v0.yaml

The current classification companion remains:

    registry/COMMAND_BOUNDARY_TABLE.v0.md

A future generated Markdown reference may eventually be:

    registry/COMMAND_REFERENCE.v0.md

But that file should not be generated in v0.6.12 unless a separate post-hardening decision explicitly approves generation.

## 6. Sidecar/API/script boundary policy

Internal sidecar commands must remain internal implementation/provider surfaces.

Cypher API rows must remain dev/pre-alpha infrastructure/API surfaces, not stable public API claims.

Historical PowerShell scripts must remain legacy continuity surfaces.

Generated docs must not flatten these into the same class as recommended dev wrapper commands or release-facing validation profiles.

## 7. Full / release-snapshot / integrated-runtime-dev policy retained

Generated docs and registry metadata must preserve:

    full:
        release-package validation ladder.

    release-snapshot:
        package-root validation.

    integrated-runtime-dev:
        live-umbrella dev composition profile.

Do not merge these meanings.

Do not treat integrated-runtime-dev as release validation.

Do not treat full as live integrated runtime.

## 8. Remaining likely work after v0.6.12

Even if missing nonclaims are closed, the next rung may still need:

    broader exact Comms CLI flag metadata;
    lifecycle_status vocabulary expansion, if desired;
    generated-reference schema tests;
    deterministic Markdown generator;
    command boundary table refresh/generation decision;
    final generation gate.

## 9. Acceptance checks

Minimum v0.6.12 checks:

    git diff --check passes;
    runner go test ./... passes;
    registry-lookup --missing-nonclaims returns zero matches or clearly bounded residuals;
    registry-lookup runner.integrated-runtime-dev still works;
    registry metadata still states registry presence is classification, not promotion;
    no generated command reference exists;
    no man pages exist;
    source status shows only carbonstack changed.
