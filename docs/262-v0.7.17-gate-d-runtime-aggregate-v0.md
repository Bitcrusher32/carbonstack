# Gate D Runtime Aggregate

Status: accepted implementation document  
Scope: v0.7.x Gate D  
Profile: `gate-d-runtime-aggregate-dev`

## Summary

Gate D introduces the first registry-visible mechanical runtime aggregate profile after Gate C closure.

The profile is intentionally named `gate-d-runtime-aggregate-dev`, not `full-runtime-dev`.

`full-runtime-dev` remains reserved until a later explicit promotion decision concludes that the material runtime aggregate justifies the name.

## What Gate D proves

Gate D proves a coherent dev/pre-alpha runtime aggregate across:

- Gate C state-substrate closure;
- explicit run-space/context candidate generation;
- C1 inventory over explicit run-space paths;
- C2 schema compatibility for generated C1/C3/C4 reports;
- C3 path policy over explicit run-space paths;
- C4 write policy over explicit run-space paths;
- workflow relay onboarding profile;
- Relay Space member restart/resume inspection profile;
- same-state integrated KeyPackage -> Welcome -> normal message send/inbox/ack proof;
- registry/reference freshness;
- zero missing nonclaims.

## Run-space/context stance

The run-space is explicit context, not a hidden shell environment and not a TUI.

The candidate context records:

- run-space root;
- profile name;
- server URL;
- account ID;
- device ID;
- Relay Space ID;
- state path;
- state root;
- sidecar directory;
- Cypher DB;
- evidence root.

Gate D does not infer authority from current directory or hidden files.

## Not full-runtime-dev

Gate D does not create or promote `full-runtime-dev`.

The `full-runtime-dev` name remains reserved until a later explicit decision, likely after more runtime, runbook, package-root, and v0.8.x maturity work.
