# CarbonStack v0.7.5 Gate B5 Prerequisite Scoped Delivery Authority v0

Status: accepted implementation authority after successful validation  
Parent closure: `docs/237-v0.7.4-gate-b-b4-invite-member-lifecycle-closure-v0.md`  
Target gate: Gate B5 KeyPackage lifecycle  
Scope: current-active routing membership for scoped inbox and scoped ACK

## 1. Purpose

This leaf collapses the former B5-P0 variance adjudication and B5-P1 correction into one bounded prerequisite.

The working environment is not required to contain unsanitized LogDocs or Breakpoints. Repository authority remains committed code, tests, accepted in-repository decision/closure documents, the command registry, and the sanitized PRIME continuity documents where relevant.

The behavioral variance is:

- scoped Relay submission already requires active sender and recipient membership;
- scoped inbox and scoped ACK previously did not re-check current active recipient membership.

Gate B5 onboarding artifacts must not remain fetchable or acknowledgeable after the recipient is disabled or has left.

## 2. Accepted contract

For Relay Space-scoped inbox:

    GET /v0/relay-spaces/{relay_space_id}/devices/{device_id}/envelopes

The target device must be a current active routing member of the exact Relay Space.

For Relay Space-scoped ACK:

    POST /v0/relay-spaces/{relay_space_id}/envelopes/{envelope_id}/ack

The actual recipient device must be a current active routing member of the exact Relay Space after envelope and recipient ownership checks succeed.

Refusal:

    HTTP 403
    recipient_not_relay_member

## 3. Persistence semantics

Disable or leave:

- revokes scoped fetch authority;
- revokes scoped ACK authority;
- does not delete the envelope;
- does not acknowledge the envelope;
- preserves queued delivery state;
- survives Cypher restart.

Reactivation:

- restores scoped fetch authority;
- restores scoped ACK authority;
- does not create a new envelope;
- allows the preserved queued envelope to be processed.

Left membership cannot be silently reactivated. Its queued envelopes remain persisted and inaccessible pending a future explicit rejoin workflow.

## 4. Error precedence

Scoped ACK preserves existing envelope and recipient ownership classification before active-membership classification:

1. unknown or wrong-space envelope -> `envelope_not_found`;
2. wrong recipient -> `recipient_mismatch`;
3. correct recipient but not active -> `recipient_not_relay_member`;
4. active correct recipient -> idempotent ACK behavior.

## 5. Boundary

This leaf controls routing/delivery authority only.

It does not implement or prove:

- KeyPackage generation;
- KeyPackage inspection;
- KeyPackage freshness;
- KeyPackage consumption;
- Welcome lifecycle;
- OpenMLS group membership;
- identity verification;
- trust promotion;
- authenticated administration;
- envelope deletion;
- production safety.

## 6. Validation authority

Permanent profile:

    relay-space-delivery-authority-dev

The profile proves:

- active recipient can fetch a queued envelope;
- disable revokes inbox and ACK;
- disabled envelope remains queued;
- disabled refusal survives restart;
- reactivation restores fetch and ACK;
- ACK transitions the original envelope to acknowledged;
- leave revokes inbox and ACK;
- left envelope remains queued;
- left refusal survives restart;
- local Comms state remains byte-identical;
- no trust or identity-candidate state is created.
