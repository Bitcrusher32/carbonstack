# Gate F F2 Failure Refusal Hygiene Guide

Status: accepted operator guide
Scope: v0.7.x Gate F F2

## Purpose

This guide records failure, refusal, and hygiene posture for the current manual-private lifecycle.

## Refusal posture

Safety-sensitive operations should refuse when required state, config, or authority is missing or ambiguous.

Examples that should refuse or stop for a new contract:

- missing explicit Cypher DB path
- missing migrations directory
- unknown deployment root
- unclear package root
- stale release helper assumptions
- request to silently migrate state
- request to silently repair state
- request to promote trust or identity without explicit contract
- request to package or upload a release during docs/runbook work

## no silent migration

Gate F F2 does not implement migration.

No silent migration is allowed.

A late Gate F migration subgate may be considered only if it is bounded, explicit, non-silent, and not excessively convoluted.

## cypher.db hygiene

The recurring repo-root cypher.db finding is a hygiene classification issue.

It should be treated as non-destructive evidence unless a later contract explicitly defines safe cleanup or ignore policy.

F2 does not delete cypher.db.

F2 does not move cypher.db.

F2 does not mutate local database state.

The intended operator DB location is inside the deployment root under state/cypher.

## not destructive cleanup

F2 is not destructive cleanup.

Do not run broad delete commands.

Do not erase local evidence.

Do not silently normalize generated state.

Do not hide hygiene findings merely to pass validation.

## Failure handling

When validation fails:

1. Preserve the log.
2. Classify whether the failure is script bug, environment issue, stale documentation, validation defect, or product defect.
3. Avoid repeating broad recon unless new behavioral surface appears.
4. Prefer targeted recovery over repeated high-cost validation ladders.
5. Generate LogDoc and Breakpoint only outside WSL after the accepted checkpoint.
