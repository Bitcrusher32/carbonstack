# v0.3.0 Release Packaging Freeze v0

Status: release packaging freeze / pre-tag checklist
Component: CarbonStack + CarbonStackComms + CarbonStackCypher
Phase: v0.2.70 final pre-v0.3.0 release packaging freeze

## 1. Purpose

This document freezes the intended v0.3.0 release package.

It does not tag v0.3.0.

It does not create the public release.

It does not add protocol behavior.

It defines what the v0.3.0 release should contain, what it must exclude, and what validation must pass before the release is cut.

## 2. Release name

Public release name:

    CarbonStack v0.3.0 experimental backbone epoch

Release class:

    pre-alpha / experimental

Primary artifact:

    Cypher + Comms OpenMLS relay backbone

Public release README:

    docs/v0.3.0-minor-epoch-release.md

## 3. What is being released

The v0.3.0 release packages the current known-good experimental backbone.

The concrete validated artifact is:

    CarbonStackComms OpenMLS sidecar
    + CarbonStackCypher real local relay server
    + opaque OpenMLS artifact envelope relay
    + payload metadata validation
    + consume-then-ack semantics
    + OpenMLS backbone self-test harness

The release is not a finished messenger.

The release is not production-certified.

The release is not externally audited.

The release is not Android-ready.

## 4. Public release source of truth

The public release source of truth is the release package itself.

Readers should not need to care about arbitrary branch heads.

The release should include the known-good source snapshots/files needed for the release.

Commit heads remain useful for LogDoc continuity and internal audit trail, but the public release should be understandable from the release README and attached source snapshots.

## 5. Component snapshots to include

The v0.3.0 release should include source snapshots for:

    carbonstack
    carbonstack-comms
    carbonstack-cypher

The release should not include `carbonstack-os` as a runnable proof component.

`carbonstack-os` may be referenced as future north-star context only.

## 7. Why source snapshots instead of hand-curated folders

Do not manually curate runnable source subsets for v0.3.0.

The self-test crosses Go packages, Rust sidecar source, scripts, test helpers, migrations, internal relay/client code, and docs.

A hand-curated subset has a high risk of omitting required files.

Use clean source snapshots with a manifest.

The manifest explains which parts are critical.

## 17. v0.3.0 release step

After this freeze, the v0.3.0 release step should:

1. run final validation;
2. confirm clean repo states;
3. create source snapshots;
4. create release manifest;
5. create checksums;
6. attach or publish release assets under the `carbonstack` repo release surface;
7. tag or mark the CarbonStack v0.3.0 experimental backbone epoch;
8. update LogDoc to v0.3.0.

No new feature work should be added during the release step.
