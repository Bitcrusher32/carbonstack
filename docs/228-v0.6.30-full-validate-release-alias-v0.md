# CarbonStack v0.6.30 full-validate-release alias v0

Status: implementation/result note for the v0.6.30C validation profile naming alias patch.

Scope: records the narrow implementation of `full-validate-release` as an exact alias to existing `full` release-package validation behavior.

This note does not describe a `full-runtime-dev` implementation.

This note does not change `full` semantics.

This note does not change `release-snapshot` semantics.

This note does not add live-dev profiles to release validation.

This note does not claim deployment readiness, production security, or hostile-server safety.

## 1. Purpose

v0.6.30A inspected the validation profile naming surface.

v0.6.30B documented the validation profile naming boundary in:

    docs/227-v0.6.30-validation-profile-naming-boundary-v0.md

v0.6.30C implements the lowest-risk alias from that model:

    full-validate-release = exact alias to current full behavior

## 2. Changed behavior

The runner now accepts:

    go run . --profile full-validate-release

Initial behavior is intentionally identical to:

    go run . --profile full

Current release validation composition remains:

    release-snapshot
    local-cypher

## 3. Unchanged behavior

`full` remains available.

`full` remains the compatibility name for release-package validation through v0.7.0.

`release-snapshot` remains package-root/layout/checksum/core validation.

`integrated-runtime-dev` remains the highest current live-dev aggregate.

Same-state profiles remain live-umbrella dev evidence.

`state-audit-dev` remains a future `full-runtime-dev` candidate only.

## 4. Nonclaims

This patch does not add:

- `full-runtime-dev`;
- live-dev runtime aggregation;
- same-state profile aggregation;
- state-audit inclusion in release validation;
- adversarial harness validation;
- hostile-server safety;
- deployment validation;
- production secure messaging;
- production E2EE;
- production security proof.

## 5. Validation expectation

Validation should prove:

- runner tests pass;
- registry lookup finds `runner.full-validate-release`;
- generated command reference is current;
- `full` and `full-validate-release` are documented as release-package validation names;
- no live-dev profile is silently added to release validation.
