# CarbonStack v0.6.26 Sender Metadata Output Warning v0

Status: output/docs cleanup after v0.6.25 envelope metadata classification and v0.6.26B output semantics scout.

## Scope

This checkpoint makes normal message inbox output explicitly label sender-device metadata as unverified relay envelope metadata.

It does not implement identity verification.

It does not change cryptographic message-open behavior.

It does not change ack/drain behavior.

It does not alter replay, malformed-payload, or provider-state semantics.

## Background

v0.6.25 classified normal application-message envelope metadata behavior.

Important result:

    wrong sender_device_id opened and acked;
    empty sender_device_id opened and acked;
    output from_device reflected relay envelope metadata;
    this is not verified identity.

Therefore `from_device` must not be presented as a verified identity field.

## Output cleanup

Normal message inbox outputs now preserve the compatibility field:

    from_device: <sender_device_id>

And add explicit trust-boundary fields:

    from_device_unverified: <sender_device_id>
    sender_identity_verified: false
    warning: from_device is relay envelope metadata, not verified identity

This is intentionally additive. The legacy `from_device` field remains for current tests, scripts, and reader continuity, but new consumers should treat `from_device_unverified` plus `sender_identity_verified: false` as the clearer contract.

## Affected commands

This applies to normal application-message inbox/open outputs:

    message-inbox-dev
    openmls-inbox-dev

This does not redefine Relay onboarding artifact sender fields such as KeyPackage/Welcome sender metadata.

## Nonclaims
