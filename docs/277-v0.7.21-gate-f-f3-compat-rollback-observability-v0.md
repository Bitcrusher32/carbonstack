# Gate F F3 Compatibility Rollback Observability

Status: accepted implementation document
Scope: v0.7.x Gate F F3
Profile: gate-f-compat-rollback-observability-dev

## Summary

Gate F F3 closes a bounded observability and refusal posture over compatibility, stale-state, rollback, downgrade, migration, and hygiene surfaces.

F3 does not implement migration.

F3 does not implement repair.

F3 does not delete or normalize state.

F3 does not create a package/runtime candidate.

F3 does not promote full-runtime-dev.

## Authority reuse

F3 deliberately reuses existing closed surfaces instead of adding a new state engine:

- C2 schema compatibility and refusal.
- C3 path policy and explicit state-root semantics.
- C4 write policy, partial-state, replay, and cleanup-boundary classification.
- F1 release/package/runtime surface classification.
- F2 operator docs/runbook authority.
- E2 Cypher terminating config inspection.

## F3 closure meaning

F3 closure means the current project has a coherent aggregate observer over the compatibility and rollback-relevant surfaces that already exist.

It means unsafe or ambiguous state should remain visible and refusal-oriented.

It does not mean automatic migration or repair is safe.

## Observed categories

The F3 profile observes:

- supported current schemas;
- unsupported newer schemas;
- missing schema on safety-sensitive artifacts;
- invalid JSON;
- legacy and unversioned state classification;
- path policy mismatch classification;
- parent traversal refusal;
- write-policy mutation and cleanup nonclaims;
- Cypher config and migration-path visibility;
- repo-root cypher.db hygiene evidence;
- release/package helper authority boundaries.

## Nonclaims

F3 does not claim:

- v0.8.0 release readiness;
- release creation or upload;
- package publication;
- package staging execution;
- package/runtime candidate validation;
- full-runtime-dev;
- migration implementation;
- repair implementation;
- destructive cleanup;
- state relocation;
- service or systemd;
- helper install;
- public ingress;
- container readiness;
- TUI;
- production readiness;
- production E2EE;
- verified identity;
- trust promotion;
- vault security;
- backup/restore;
- PQ/hybrid migration;
- Android;
- CarbonStackOS implementation.
