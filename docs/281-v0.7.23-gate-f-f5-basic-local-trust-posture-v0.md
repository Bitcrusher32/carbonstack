# Gate F F5 Basic Local Trust Posture

Status: accepted implementation document
Scope: v0.7.x Gate F F5
Profile: gate-f-basic-local-trust-posture-dev

## Summary

Gate F F5 adds a barebones local manual trust candidate posture before package/runtime candidate validation.

F5 is intentionally not verified identity and not full trust promotion.

The point is to make the current identity-domain split explicit and to provide a local manual acceptance evidence path that can be expanded during v0.8.x work.

## Current identity-domain model

F5 distinguishes four domains:

- Cypher account/device identity is coordination and routing identity.
- Comms local trust/candidate fingerprint is local operator policy evidence.
- OpenMLS sidecar device label and KeyPackage reference are cryptographic group material.
- Relay Space membership is routing and membership coordination.

These domains are correlated by operator evidence in v0.7.x. They are not cryptographically unified.

## Commands added in Comms

basic-local-trust-posture-dev prints a JSON report over observed domains.

basic-local-trust-accept-dev records an explicit local manual candidate acceptance event.

The accept command requires accept-candidate and a reason.

## Required safety rules

Relay membership does not promote trust.

Successful Welcome or MLS join does not promote trust.

Local acceptance is not verified identity.

Local acceptance is not secure enrollment.

Local acceptance is not a server-hostile identity replacement proof.

Local acceptance does not cryptographically bind Cypher, Comms, and OpenMLS identities.

## Nonclaims

F5 does not claim verified identity, full trust promotion, secure enrollment, production E2EE, package/runtime candidate validation, release readiness, release creation, package publication, full-runtime-dev, migration, repair, destructive cleanup, service/systemd/helper install, public ingress, container, TUI, vault, backup/restore, PQ, Android, or CarbonStackOS.
