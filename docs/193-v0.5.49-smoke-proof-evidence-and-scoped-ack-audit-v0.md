## 7. Scoped ack audit

Current allowed scoped ack behavior:

    KeyPackage is not acked by the v0.5.48 smoke script.
    Welcome is not acked by default.
    Welcome may be acked only with ACK_AFTER_JOIN=1 / --ack-after-join.
    Welcome ack may occur only after sidecar conversation-join succeeds.

Required audit observations:

    keypackage_acked remains false in add-member output;
    welcome_acked remains false before join;
    welcome_acked remains false when ACK_AFTER_JOIN is unset or 0;
    welcome_acked becomes true only when ACK_AFTER_JOIN=1 and join succeeds;
    ack output includes the scoped envelope ID and acknowledged timestamp;
    no output implies ack is proof of identity or trust.

## 8. Failure evidence still required before validation profile

Before a validation profile exists, collect or test:

    missing KeyPackage behavior;
    missing Welcome behavior;
    sidecar add-member failure behavior;
    sidecar join failure behavior;
    Welcome write failure behavior;
    proof no ack on write failure;
    proof no ack on sidecar join failure;
    proof no ack by default;
    proof scoped ack only after join success when requested.

Existing unit tests cover parts of this behavior, but the smoke proof should still document what was actually exercised.

## 9. Trust and candidate nonmutation audit

The smoke proof must not mutate:

    trust.json;
    trust-events.jsonl;
    identity-candidates.json;
    verified device state;
    candidate acceptance state;
    key replacement state;
    recovery state.

Recommended audit method before a validation profile:

    identify the trust/candidate paths for the test states;
    record whether they exist before the run;
    hash or list them before the run where safe;
    hash or list them after the run where safe;
    confirm no unexpected trust/candidate mutation occurred.

If no trust/candidate stores are present, record that absence.

Do not treat absence as a proof of full safety.

## 10. Registry and public-surface audit

Confirm:

    all callable commands/scripts used by the smoke proof have registry coverage;
    smoke script registry entry remains dev/pre-alpha;
    include_in_front_readme remains false;
    no front README promotion occurred;
    no public CLI readiness is claimed.

Hidden registry coverage is allowed.

Public CLI/readme promotion remains deferred.

## 11. Validation-profile blocker

A local-dev validation profile remains blocked until:

    smoke evidence is captured at least once;
    setup ownership is exact;
    generated state roots are known;
    cleanup boundaries are defined;
    failure behavior is repeatable;
    trust/candidate nonmutation is checked;
    registry/public-surface boundaries are checked;
    the profile can state exactly what it proves and what it does not prove.
