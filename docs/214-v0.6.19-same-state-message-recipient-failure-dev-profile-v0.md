# CarbonStack v0.6.19 Same-State Message Recipient Failure Dev Profile v0

Status: implementation checkpoint for third same-state normal-message failure-path hardening profile.

## Scope

This document records the committed profile:

    go run . --profile same-state-message-recipient-failure-dev --root <umbrella root> --clean-generated

The profile proves a narrow failure rule inside the same-state universe:

    wrong recipient/device/sidecar attempts must not falsely open, ack, or drain Bob's inbox.

It then proves the valid Bob path remains recoverable by opening with the correct Bob state, Bob sidecar label, conversation, message label, and explicit `--ack`.

## Why this exists

v0.6.16 added the positive-path profile:

    same-state-integrated-dev

v0.6.17 added the wrong-conversation no-ack/no-drain profile:

    same-state-message-failure-dev

v0.6.18 added the unsupported normal-message content-type no-ack/no-drain profile:

    same-state-message-unsupported-dev

v0.6.19 adds wrong recipient/device/sidecar no-false-success behavior without claiming adversarial harness coverage or identity verification.

## Sequence

The profile performs:

1. Build a temporary Cypher binary.
2. Start one temporary Cypher server with one temporary DB.
3. Initialize Alice/Bob Comms state files against that server.
4. Create/claim dev invites and register devices.
5. Create one Relay Space and routing members.
6. Create Alice/Bob sidecar identities.
7. Alice creates one conversation.
8. Bob submits KeyPackage.
9. Alice add-member creates Welcome.
10. Bob joins with ACK_AFTER_JOIN enabled.
11. Alice sends a normal application message to Bob.
12. Case A: Alice state + Alice sidecar attempts `message-inbox-dev --ack`.
13. Case B: Bob state + Alice sidecar attempts `message-inbox-dev --ack`.
14. Case C: Bob state + missing sidecar attempts `message-inbox-dev --ack`.
15. Assert each wrong attempt does not report `message opened`, `acked: true`, or `ack_delivery_state: acknowledged`.
16. Assert each wrong attempt does not change ack count.
17. Assert each wrong attempt does not drain Bob's inbox.
18. Bob opens the same message with correct Bob state + Bob sidecar.
19. Assert correct open succeeds and acks.
20. Assert Bob inbox is empty after correct open/ack.

## Expected wrong-attempt evidence

Wrong attempts may fail/skips at different layers:

    Alice state + Alice sidecar may skip an unsupported onboarding artifact in Alice's inbox.
    Bob state + Alice sidecar may fail sidecar message-open, for example CannotDecryptOwnMessage.
    Bob state + missing sidecar may fail because provider/conversation storage is missing.

The invariant is shared:

    opened_envelopes: 0
    no message opened
    no acked: true
    no ack_delivery_state: acknowledged
    ack count unchanged
    Bob inbox count unchanged

## Relationship to future adversarial harness

This is a deterministic failure-path hardening profile, not an adversarial harness.

A later harness may call this profile or reuse its logic after an explicit aggregation/profile policy exists.

Do not use this profile alone to claim hostile-server safety, identity verification, or malicious relay resistance.
