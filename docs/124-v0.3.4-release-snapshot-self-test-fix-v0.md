# Release Snapshot Self-Test Fix v0

Status: fix record / public testing path
Phase: v0.3.4 backbone maturation
Related recon: docs/123-v0.3.0-clean-snapshot-self-test-recon-v0.md

## 1. Purpose

This document records the v0.3.4 fix for the clean release snapshot self-test issue found during v0.3.3.

v0.3.3 proved that the underlying v0.3.0 backbone proof could run from extracted source snapshots, but the public Comms self-test wrapper failed because the Rust artifact guard assumed a Git working tree.

Release ZIP/source snapshots intentionally do not include `.git/`.

## 2. Problem

The public Comms self-test wrapper calls:

    carbonstack-comms/scripts/check-no-rust-artifacts.ps1

Before v0.3.4, that script called Git without safely handling source snapshots that do not contain `.git/`.

In a release source snapshot without `.git/`, the script could print:

    fatal: not a git repository

The underlying OpenMLS real-Cypher lifecycle proof passed, but the wrapper failed after the proof when the artifact guard returned a Git error.

## 3. Fix

`check-no-rust-artifacts.ps1` now supports two modes.

Git working tree mode:

    use Git to check tracked files;
    fail if generated/private/build artifacts are tracked.

Source snapshot fallback mode:

    detect that `.git/` metadata is unavailable;
    print a clear fallback message;
    scan the filesystem for generated/private/build artifacts;
    exit successfully in non-strict mode while reporting findings as informational.

This lets public source snapshots run the self-test without requiring Git metadata.

## 4. Validation result

The v0.3.4 fix was validated against a no-Git source-copy snapshot.

Passing checks:

    public self-test from no-Git source snapshot;
    public self-test -Full from no-Git source snapshot;
    CarbonStack validate-local from no-Git source snapshot;
    CarbonStack validate-local from the live working repos.

## 5. Why non-strict fallback is necessary

The OpenMLS sidecar tests generate local state and Rust build output while running.

After validation, a filesystem scan may find:

    target/
    .carbonstack-openmls-sidecar-state/
    provider-storage.json
    signer.json
    temporary SQLite DBs
    Rust build executables

These are post-validation outputs.

They must not be shipped in release source snapshots, but their presence after running tests does not mean the release snapshot shipped them.

## 6. What this fix does not claim

This fix does not prove:

    production readiness;
    production E2EE;
    hostile-server safety;
    metadata privacy;
    Android readiness;
    secure vault/storage;
    Linux portability;
    external audit;
    certification.

It only improves public testability of the experimental backbone from release/source snapshots.

## 7. Release note

The original v0.3.0 release remains historical.

v0.3.4 should be treated as the testing bug hotfix release for public source-snapshot self-testing.
