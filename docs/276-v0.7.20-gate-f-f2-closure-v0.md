# Gate F F2 Closure

Status: accepted closure document
Scope: v0.7.x Gate F F2

## Closure meaning

Gate F F2 is closed when gate-f-operator-docs-runbook-dev passes and the registry contains runner.gate-f-operator-docs-runbook-dev.

Closure means the manual-private lifecycle has operator docs/runbook authority for:

- manual-private lifecycle
- explicit config/env validation
- release/package authority
- failure/refusal/hygiene
- F2 closure state

## Gate state after F2

GATE_D_STATUS=closed
GATE_E_STATUS=closed
GATE_F_STATUS=open_f1_f2_closed_f3_not_started
GATE_F_F1_STATUS=closed
GATE_F_F2_STATUS=closed
GATE_F_F3_STATUS=not_started
BREAKPOINT_REQUIRED_AFTER_F2=true

## Required handoff

After F2, generate a private Markdown LogDoc and lean JSON Breakpoint before starting Gate F F3.

Gate F F3 should not start until that breakpoint is accepted.

## Gate F F3 expected direction

Gate F F3 should target compatibility, stale-state, rollback observability, and refusal posture.

Migration implementation is not automatically authorized by F2.

Package/runtime candidate validation is not automatically authorized by F2.

full-runtime-dev promotion is not automatically authorized by F2.

## Nonclaims

F2 does not create a release, upload a release, stage a package, publish a package, promote full-runtime-dev, implement migration, install service/systemd/helper surfaces, add public ingress, add containers, add TUI, claim production readiness, claim production E2EE, verify identity, promote trust, add vault security, add backup/restore, add PQ/hybrid support, add Android, or implement CarbonStackOS.
