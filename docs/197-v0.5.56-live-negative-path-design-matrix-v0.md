## 3. Current coverage map

### 3.1 Already covered at Cypher HTTP/API layer

Existing Cypher Relay Space scoped-envelope tests cover:

    scoped submit returns relay_space_id and queued state;
    scoped inbox returns only matching Relay Space envelopes;
    scoped ack returns relay_space_id and acknowledged state;
    scoped inbox becomes empty after scoped ack;
    wrong Relay Space ack rejects with envelope_not_found;
    wrong recipient ack rejects with recipient_mismatch;
    missing Relay Space scoped submit/inbox rejects.

Interpretation:

    wrong Relay Space ack and wrong recipient ack do not need to be duplicated immediately inside the long relay-openmls-join-dev profile.

They can be re-surfaced later in a small runner negative profile only if release-readiness requires runner-level proof.

### 3.2 Covered at runner helper/assertion layer

v0.5.55 covers runner-local negative helper behavior:

    missing KeyPackage delivery state is refused during compact result collection;
    missing Welcome delivery state is refused during compact result collection;
    DB assertion fails on missing Welcome;
    DB assertion fails on unexpected ack in no-ack mode;
    DB assertion fails on missing ack in ACK_AFTER_JOIN mode;
    DB assertion fails on queued Welcome in ACK_AFTER_JOIN mode;
    DB assertion fails on missing KeyPackage;
    trust/candidate file presence fails absence checks;
    count mismatch fails as expected.

Interpretation:

    the runner can detect bad post-run DB/result states, but this is not the same as live failure-path exercise.

### 3.3 Covered by profile positive path

`relay-openmls-join-dev` currently covers:

    no-ack KeyPackage -> add-member -> Welcome -> join;
    ACK_AFTER_JOIN KeyPackage -> add-member -> Welcome -> join -> scoped Welcome ack;
    fresh runner-owned temp roots;
    dynamic local Cypher ports;
    unique sidecar labels;
    stale sidecar-device refusal before profile run;
    trust/candidate absence checks before and after;
    exact DB assertions for no-ack and ACK_AFTER_JOIN.

Interpretation:

    this is strong positive-path validation, not hostile-server validation or broad failure-path proof.

## 4. Remaining negative/failure-path gaps

Remaining gaps should be separated by ownership.

### 4.1 Cypher-owned gaps

Candidate Cypher-owned gaps:

    wrong Relay Space ack rejection;
    wrong recipient ack rejection;
    missing Relay Space scoped submit/inbox rejection;
    idempotent ack behavior;
    ack cannot cross Relay Space boundary.

Current status:

    already materially covered at Cypher HTTP/API test level.

Recommended action:

    do not duplicate immediately in the long runner profile.
    Consider a later small runner-facing "relay-space-ack-negative-dev" profile only if release-snapshot/public evidence needs it.

### 4.2 Comms-owned gaps

Candidate Comms-owned gaps:

    no KeyPackage envelope;
    no Welcome envelope;
    sidecar conversation-add-member failure;
    sidecar conversation-join failure;
    Welcome write failure;
    proof no ack on Welcome write failure;
    proof no ack on sidecar join failure;
    ack client failure after successful join.

Current status:

    partially covered by command/unit surfaces and runner DB assertions, but not yet as dedicated live negative harnesses.

Recommended action:

    implement these as targeted Comms tests or small dev harnesses, not by bloating `relay-openmls-join-dev`.

### 4.3 Runner-owned gaps

Candidate runner-owned gaps:

    compact summary refuses missing scalar rows;
    DB assertions fail on bad post-run state;
    stale sidecar labels refuse before run;
    trust/candidate file presence refuses;
    generated temp root cleanup remains bounded.

Current status:

    mostly covered by v0.5.54/v0.5.55 helper tests.

Recommended action:

    keep runner profile positive-path for now.
    Add separate negative runner profile only after Comms/Cypher targeted tests mature.

### 4.4 Artifact/hygiene gaps

Current artifact-scan review hit:

    carbonstack-cypher/cypher.db

Current interpretation:

    repo-local DB is not used by relay-openmls-join-dev, which uses runner-owned temp DBs.
    It remains a hygiene/release-readiness item.

Recommended action:

    defer deletion/cleanup to a separate explicit hygiene rung.
    Do not silently delete it as part of negative-path work.

## 6. Placement rule

Do not put every negative case into `relay-openmls-join-dev`.

That profile should remain the positive-path local/dev proof unless a separate decision changes its scope.

Negative cases should prefer:

    Cypher HTTP/API tests for routing/ack authorization;
    Comms command tests for sidecar/write/join/ack failure behavior;
    runner helper tests for DB/assertion/output behavior;
    a separate runner negative profile only when live runner evidence is specifically valuable.
