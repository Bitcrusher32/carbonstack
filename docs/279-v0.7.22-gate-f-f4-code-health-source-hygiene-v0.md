# Gate F F4 Code Health Source Hygiene

Status: accepted implementation document
Scope: v0.7.x Gate F F4
Profile: gate-f-code-health-source-hygiene-dev

## Summary

Gate F F4 closes a bounded code-health and source-hygiene classification layer before package/runtime candidate work.

F4 does not create a package/runtime candidate.

F4 does not run package staging.

F4 does not create or upload a release.

F4 does not implement migration, repair, destructive cleanup, or state relocation.

## Accepted hygiene policies

Python cache policy:

- Python bytecode caches are generated local artifacts.
- carbonstack ignores __pycache__ directories and pyc files.
- registry rendering should prefer Python no-bytecode behavior in automation.

cypher.db policy:

- repo-root cypher.db remains a visible non-destructive hygiene classification target.
- F4 does not delete cypher.db.
- F4 does not move cypher.db.
- F4 does not mutate local database state.
- The intended operator DB location remains deployment root state/cypher.

historical LogDoc archive policy:

- sanitized-project-logdoc-list is historical provenance.
- It can dominate keyword scans because it intentionally preserves old release and package history.
- F4 classifies it as provenance rather than current source defect evidence.

helper script policy:

- release and package helper scripts are statically classified.
- Shell scripts may be syntax checked.
- Python scripts may be py-compiled with Python bytecode disabled.
- Helper scripts are not executed as release actions by F4.
