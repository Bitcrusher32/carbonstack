# CarbonStack v0.6.23 Same-State Message Malformed Payload Dev Profile v0

Status: implementation checkpoint after v0.6.23A malformed normal-message payload recon.

## Scope

This document records the committed profile:

    go run . --profile same-state-message-malformed-payload-dev --root <umbrella root> --clean-generated

The profile proves a narrow same-state failure invariant:

    malformed normal application-message payloads do not falsely open;
    malformed normal application-message payloads do not ack;
    malformed normal application-message payloads do not drain Bob's queued normal-message inbox;
    malformed normal application-message payloads do not mutate conversation provider storage;
    malformed normal application-message payloads do not rewrite the envelope;
    restoring the original payload allows correct open/ack recovery.

## Covered mutation families

The profile covers:

    invalid ciphertext_b64 storage shape;
    valid base64 random bytes;
    valid base64 truncated original OpenMLS message bytes;
    valid base64 single-byte-flipped original OpenMLS message bytes;
    valid base64 empty bytes;
    valid base64 original bytes with appended junk.

## Expected evidence

For every malformed case:

    message open failed;
    opened_envelopes: 0;
    open_failures: 1;
    ack_failures: 0;
    acked: false;
    envelope ack count unchanged;
    Bob application-message inbox count unchanged;
    provider-storage.json fingerprint unchanged;
    envelope payload fingerprint unchanged.

For every restored payload:

    message opened;
    ack_delivery_state: acknowledged;
    acked: true;
    opened_envelopes: 1;
    open_failures: 0;
    ack_failures: 0;
    Bob application-message inbox count becomes 0.

## Relationship to prior profiles

`same-state-message-malformed-payload-dev` is different from:

    same-state-message-unsupported-dev

The unsupported profile mutates normal application-message `content_type`.

This profile keeps `content_type` valid and mutates the application-message payload/ciphertext storage.

It is also different from:

    same-state-message-failure-dev

That profile checks wrong-conversation message-open failure.

It is also different from:

    same-state-message-recipient-failure-dev

That profile checks wrong recipient/device/sidecar no-false-success behavior.

It is also different from v0.6.22 sidecar state-authority classification.

That checkpoint classified provider state and metadata authority. This profile tests malformed message payload behavior.
