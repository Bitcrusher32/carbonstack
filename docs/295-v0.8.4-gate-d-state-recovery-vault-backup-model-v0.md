## Current ownership model

`carbonstack` records the model, registry, report schema, docs, validation profile, and nonclaims.

`carbonstack-comms` owns component-local state classification because Comms carries local state, OpenMLS sidecar state references, trust/candidate state, receipts, workflow state, and local path-policy surfaces.

`carbonstack-cypher` remains coordination/server inventory only. Cypher SQLite schema, DB path, envelope delivery state, account/device/member records, and migration facts may be inventoried, but Cypher is not a backup/restore/vault authority.

`carbonstack-os` remains future constrained-appliance context only.

## Gate C trust-candidate interaction

Gate C trust-candidate state is referenced inventory only. Changed-lineage warnings are referenced warning-only. Demotion/revocation state is referenced event-only. None of these become a backup target, restore authority, migration target, repair target, or silent trust-import surface in Gate D.

## Nonclaims

Gate D does not claim:

- production vault;
- encryption-at-rest;
- secure key storage;
- production backup/restore;
- migration safety;
- secret-bearing backup restore;
- hardware-backed storage;
- automatic migration;
- silent repair;
- silent signer/provider/group regeneration;
- silent trust import;
- destructive cleanup;
- verified identity;
- trust promotion.

## Future pipeline bridge

The full backup/restore/vault pipeline remains necessary before a serious v0.9.x external adversarial red-team analysis. Gate D creates the current model and safe classification bridge toward that pipeline. Future work must explicitly decide how secret-bearing vault, backup, restore, hardware-backed storage, recovery keys, and operator UX are implemented and adversarially tested.
