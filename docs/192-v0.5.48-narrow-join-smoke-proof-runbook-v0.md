# v0.5.48 narrow join smoke-proof runbook

Status: runbook / dev smoke-proof checkpoint
Phase: v0.5.x Relay Space + OpenMLS dev join scaffold stabilization
Scope: one narrow local/dev KeyPackage -> add-member -> Welcome -> join smoke proof
Date: 2026-06-08 local session

## 1. Purpose

v0.5.48 defines a narrow smoke proof for the current Relay Space OpenMLS dev scaffold.

This checkpoint may add a runbook and a dev helper script.

It does not add:

    validation profile;
    public README promotion;
    new Comms app commands;
    command registry entries;
    new Cypher routes;
    trust.json mutation;
    identity-candidates.json mutation;
    local-backbone claim;
    hostile-server harness;
    production/deployment claims.

## 2. What this smoke proof may prove

This smoke proof may prove only that one local/dev sequence can be performed with the current scaffold:

    Bob exports a KeyPackage and submits it through Relay Space to Alice.
    Alice retrieves Bob's KeyPackage, writes it, runs sidecar conversation-add-member, and submits the produced Welcome back through Relay Space.
    Bob retrieves the Welcome, writes it, runs sidecar conversation-join, and may optionally scoped-ack the Welcome after join success.

This is a development proof of command composition.

It is not a security proof.

## 3. What this smoke proof must not claim

Do not describe this smoke proof as:

    local-backbone;
    production secure messaging;
    hostile-server safety;
    metadata privacy;
    verified identity;
    secure enrollment;
    mature OpenMLS provider live-flow;
    public CLI readiness;
    deployment readiness;
    audit or certification.

## 4. Required preconditions

Operator must already have:

    a local Cypher server running;
    two ready Comms states, one for Alice and one for Bob;
    Alice and Bob device IDs;
    one Relay Space ID routable by both devices;
    Alice and Bob OpenMLS sidecar device labels;
    an Alice-side OpenMLS conversation label already created;
    a Bob-side conversation label to join into;
    current git umbrella checkout;
    current v0.5.48-era Comms commands available.

The smoke script intentionally does not create accounts, devices, Relay Spaces, or conversations.

Those setup steps remain outside this smoke proof until a later validation-profile design defines generated-state ownership.

## 5. Environment variables for the helper script

Required:

    ALICE_STATE
    BOB_STATE
    RELAY_SPACE_ID
    ALICE_DEVICE_ID
    BOB_DEVICE_ID
    ALICE_SIDECAR_LABEL
    BOB_SIDECAR_LABEL
    ALICE_CONVERSATION_LABEL
    BOB_CONVERSATION_LABEL

Optional:

    COMMS_DIR
    ACK_AFTER_JOIN

If ACK_AFTER_JOIN=1, the final join command uses --ack-after-join.

## 6. Manual command sequence

From carbonstack-comms:

    go run ./cmd/comms openmls-relay-keypackage-submit-dev \
      --state "$BOB_STATE" \
      --relay-space "$RELAY_SPACE_ID" \
      --to-device "$ALICE_DEVICE_ID" \
      --sidecar-device-label "$BOB_SIDECAR_LABEL"

    go run ./cmd/comms openmls-relay-add-member-dev \
      --state "$ALICE_STATE" \
      --relay-space "$RELAY_SPACE_ID" \
      --sidecar-device-label "$ALICE_SIDECAR_LABEL" \
      --conversation "$ALICE_CONVERSATION_LABEL" \
      --welcome-to-device "$BOB_DEVICE_ID"

    go run ./cmd/comms openmls-relay-join-dev \
      --state "$BOB_STATE" \
      --relay-space "$RELAY_SPACE_ID" \
      --sidecar-device-label "$BOB_SIDECAR_LABEL" \
      --conversation "$BOB_CONVERSATION_LABEL"

Optional ack-after-join variant:

    go run ./cmd/comms openmls-relay-join-dev \
      --state "$BOB_STATE" \
      --relay-space "$RELAY_SPACE_ID" \
      --sidecar-device-label "$BOB_SIDECAR_LABEL" \
      --conversation "$BOB_CONVERSATION_LABEL" \
      --ack-after-join

## 7. Expected evidence

KeyPackage submit output should include:

    command: openmls-relay-keypackage-submit-dev
    status: sent
    content_type: application/vnd.carbonstack.openmls.keypackage
    envelope_id:

Add-member output should include:

    command: openmls-relay-add-member-dev
    status: welcome_created_and_sent
    sidecar_command: conversation-add-member
    welcome_envelope_id:
    keypackage_acked: false
    welcome_acked: false

Join output without ack should include:

    command: openmls-relay-join-dev
    status: joined
    sidecar_command: conversation-join
    ack_requested: false
    welcome_acked: false

Join output with ACK_AFTER_JOIN=1 should include:

    command: openmls-relay-join-dev
    status: joined
    ack_requested: true
    welcome_acked: true
    ack_envelope_id:
    ack_delivery_state:

## 8. Ack boundary

Ack is not proof of identity.

Ack is not local verification.

Ack is only a delivery/local-processing signal.

For this smoke proof:

    KeyPackage is not acked.
    Welcome is not acked by default.
    Welcome may be acked only by explicit ACK_AFTER_JOIN=1 / --ack-after-join.
    The command implementation gates that ack after sidecar conversation-join success.

## 9. Trust and candidate boundary

The smoke proof must not mutate:

    trust.json;
    trust-events.jsonl;
    identity-candidates.json;
    verified device state;
    candidate acceptance state;
    key replacement state;
    recovery state.

Any provider/OpenMLS identity material remains unverified until a future candidate/review/verification path handles it.

## 10. Validation-profile blocker

This smoke proof is not a validation profile.

A validation profile remains blocked until:

    setup state is isolated and generated-state ownership is exact;
    failure behavior is captured repeatably;
    trust/candidate nonmutation is checked;
    registry/front README claim boundaries are checked;
    the profile can state exactly what it proves and does not prove.
