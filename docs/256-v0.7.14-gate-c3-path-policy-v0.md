# Gate C3 Path Policy

Status: accepted implementation document  
Scope: v0.7.x Gate C3  
Command: `state-path-policy-dev`  
Profile: `state-path-policy-dev`

## Summary

Gate C3 introduces explicit path policy and state-root semantics after C1 inventory and C2 schema compatibility.

C3 does not migrate, repair, relocate, delete, or normalize existing state. It classifies supported roots and refuses only clearly unsafe path policy cases such as parent traversal.

## Command

`state-path-policy-dev`

Important flags:

- `--state`
- `--state-root`
- `--sidecar-dir`
- `--cypher-db`
- `--validator-temp-root`
- `--evidence-root`
- `--output`
- `--allow-refusal-exit-zero`

## Report schema

`carbonstack-state-path-policy-report/v0`

## Path policy

C3 defines:

- `.carbonstack-comms` as the preferred canonical Comms-owned root;
- explicit `--state` compatibility as preserved;
- `--state-root` as a C1/C3 inspection/policy surface, not a migration trigger;
- derived sibling roots beside `--state` as supported where already established;
- sidecar state as sidecar-owned and classified only;
- Cypher DB state as Cypher-owned and classified only;
- validator temp roots as generated validation state;
- evidence roots as evidence-only.

## Explicit root mismatch

When `--state` and `--state-root` imply different roots, C3 classifies the mismatch rather than refusing by default. This prevents path inspection from becoming brittle.

## Unsafe path refusal

C3 refuses clear parent traversal path cases. Broader symlink and filesystem hardening belongs to later C4/C5 work unless a concrete issue appears earlier.

## Nonclaims

C3 does not claim:

- C4 atomicity/lock closure;
- C5 Gate C closure;
- migration;
- repair;
- state relocation;
- cleanup implementation;
- vault security;
- backup/restore safety;
- trust promotion;
- verified identity;
- Cypher/MLS reconciliation;
- deployment readiness;
- full-runtime-dev;
- Gate D runtime aggregate;
- production E2EE;
- Android or CarbonStackOS implementation.
