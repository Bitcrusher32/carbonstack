# Gate B8 Workflow Engine

Status: accepted implementation document  
Scope: v0.7.x Gate B8  
Command: `workflow-relay-onboarding-dev`  
Profile: `workflow-relay-onboarding-dev`

## Summary

B8 introduces a reusable noninteractive workflow report/evaluator above the B4/B5/B6/B7 dev leaves.

This is not a public UX, TUI, or full operational aggregate. It is the first reusable workflow layer that preserves explicit lower-level boundaries while classifying ready, partial, and refused relay onboarding state.

## Command

`workflow-relay-onboarding-dev` evaluates a Relay onboarding state bundle.

Required flags:

- `--relay-space`
- `--cypher-member-state`

Important optional flags:

- `--state`
- `--workflow-id`
- `--mls-group-state`
- `--sidecar-dir`
- `--sidecar-device-label`
- `--conversation`
- `--conversation-state`
- `--keypackage-receipt`
- `--welcome-receipt`
- `--report-root`
- `--allow-refusal-exit-zero`

## Behavior

The command emits a durable workflow report with explicit stages:

- `state_ready`
- `cypher_mls_mismatch`
- `keypackage_receipt`
- `welcome_receipt`
- `workflow_result`

It returns `workflow_ready` only when:

- B7 state is aligned;
- KeyPackage receipt is present, persisted, and ACKed;
- Welcome receipt is present, persisted, joined, and ACKed.

It refuses:

- B7 mismatch classifications;
- missing KeyPackage receipts;
- missing Welcome receipts;
- incomplete local consume/join state.

## Boundary

B8 preserves:

- KeyPackage receipt identity;
- Welcome receipt identity;
- ACK-after-persist discipline;
- ACK-after-join discipline;
- Cypher/MLS mismatch refusal;
- trust/identity nonclaims.

B8 does not:

- repair state;
- rejoin automatically;
- mutate trust or identity candidates;
- verify identity;
- reconcile Cypher and MLS;
- close Gate B;
- implement `full-runtime-dev`.
