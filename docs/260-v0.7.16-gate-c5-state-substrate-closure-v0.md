# Gate C5 State Substrate Closure

Status: accepted implementation document  
Scope: v0.7.x Gate C5  
Profile: `gate-c-state-substrate-closure-dev`

## Summary

Gate C5 closes Gate C as the bounded state-substrate enforcement lane.

C5 is not a new runtime feature surface. It proves the C1-C4 surfaces together:

- C1 inventory and authority map;
- C2 schema/version compatibility and refusal;
- C3 path policy and explicit state-root semantics;
- C4 write policy, atomicity, lock, partial-state, replay, and cleanup-boundary classification.

## Retry note

The first C5 implementation script failed in shadow generation because it used a brittle exact multi-line anchor against `state_schema_compat_dev.go`, then incorrectly continued to `gofmt` after generation failed. The retry uses robust map insertion and hard-stops after generation failure.

## C4 label/schema compatibility correction

C4 exposed a continuity hazard: a validator step label said C2 accepted the C3 path-policy schema, while the actual command used the wrong kind and refused under `--allow-refusal-exit-zero`.

C5 corrects this by giving C3 and C4 reports explicit C2 schema kinds:

- `path-policy-report`
- `write-policy-report`

This preserves strict kind/schema matching. A path-policy report is not treated as a state-substrate inventory report.

## Closed behavior

C5 closes when:

- C1 profile passes;
- C2 profile passes;
- C3 profile passes;
- C4 profile passes;
- C3/C4 report schemas are accepted by explicit C2 kinds;
- registry/reference checks pass;
- missing nonclaims remain zero;
- Gate B closure authority remains present;
- Gate D is not started.

## Nonclaims

C5 does not claim:

- Gate D runtime aggregate;
- full-runtime-dev;
- migration;
- silent repair;
- state relocation;
- runtime writer rewiring;
- cleanup implementation;
- destructive cleanup;
- vault security;
- backup/restore safety;
- trust promotion;
- verified identity;
- Cypher/MLS reconciliation;
- deployment readiness;
- production E2EE;
- PQ/hybrid migration;
- Android or CarbonStackOS implementation.
