# Gate C v0.8.x Local Trust Candidate Contract

Status: dev/pre-alpha Gate C contract artifact  
Checkpoint: v0.8.3 Gate C local trust promotion candidate model  
Scope: local trust candidate schema, trust-state model, loud lineage warnings, nonclaim preservation, and adversarial seed-case carry-forward  

## Purpose

Gate C creates a local identity/trust promotion candidate model that is explicit enough to attack.

Gate C is not verified identity. Gate C is not secure enrollment. Gate C is not hostile-server identity replacement proof. Gate C is not real-world person verification. Gate C is not automatic trust promotion.

## Component boundary

`carbonstack` owns docs, registry/reference classification, adversarial case registry, validation profile, and claim/nonclaim report surfaces.

`carbonstack-comms` owns local trust/candidate runtime behavior because the Comms client is the local state and OpenMLS-sidecar integration surface.

`carbonstack-cypher` remains coordination only. It must not become a trust, identity, plaintext, MLS, or verified membership authority.

`carbonstack-os` remains future constrained-appliance direction only.

## Required model

```text
candidate_observed
-> operator_review_required
-> promoted_local_trust
-> changed_lineage_warning
-> demoted
-> revoked
-> unknown_or_untrusted
```

The model must preserve this rule:

```text
candidate state is not promoted without explicit operator action
```

## Required behavior

Gate C must keep these boundaries loud:

- Relay membership is not trust.
- MLS join is not trust.
- Provider observation is not trust.
- Candidate state is not promoted without explicit operator action.
- Changed signer/device/key lineage is loud.
- Unknown or changed trust state can be refused for safety-sensitive workflows.
- Overrides, if any, are explicit, logged, non-default, and dev/pre-alpha scoped.

## Nonclaims

Gate C does not claim production verified identity, secure enrollment, hardware-backed identity, real-world person verification, automatic trust promotion, hostile-server identity replacement proof, trust from Relay membership, trust from MLS join, trust from provider observation, cryptographic binding across Cypher/Comms/OpenMLS identities, production security, production E2EE, external audit, or external pen-test completion.

## Validation posture

This Gate C implementation uses focused validation unless integration behavior is materially touched. Broad ladders remain allowed for full CarbonStack integration or closure, but they are not required for this candidate-model seed.
