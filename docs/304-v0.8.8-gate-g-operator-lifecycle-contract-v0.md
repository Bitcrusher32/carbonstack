# v0.8.8 Gate G Operator Lifecycle Contract v0

## Status

Gate G3 implementation contract.

Schema marker: `carbonstack-gate-g-operator-lifecycle-contract/v0`

## Frozen G2 decisions

```text
CONTAINERS=deferred_late_v0.9.x_or_v0.10.0
FULL_RUNTIME_DEV=reserved_not_promoted
PREFERRED_AGGREGATE=operator-lifecycle-dev
G3=operator_lifecycle_engine_mutation
G4=conditional_local_private_service_systemd_helper_substrate
G5=conditional_public_ingress_threat_model_prototype_substrate
PUBLIC_INGRESS_DEFAULT=disabled
PUBLIC_INGRESS_ALLOWED_IN_V0_8_X=yes_but_only_as_explicit_G5_prototype_or_threat_model_substrate
PUBLIC_INGRESS_GATE_H_REQUIREMENT=mandatory_if_G5_exists
```

## Purpose

`operator-lifecycle-dev` is the preferred Gate G operator lifecycle aggregate after the G2 placement freeze.

It is allowed to summarize the current lifecycle posture and select the next operator-safe lanes. It is not allowed to silently run every dev profile, promote `full-runtime-dev`, install services, open public ingress, create containers, create a release, mutate package surfaces, or claim production readiness.

## Output rule

The profile must emit safe-summary stdout by default. Sensitive, high-volume, or local-environment detail belongs in evidence-root reports produced by outer validation scripts.

`ADV-NATIVE-LOG-LEAKAGE-001` is carried into Gate G as unresolved high log-hygiene debt. The aggregate must not amplify same-state sensitive markers into a public-style operator summary.

## Lifecycle stages

The Gate G lifecycle model uses these stages:

- `g3_operator_lifecycle_engine`
- `g4_local_private_service_systemd_helper_substrate`
- `g5_public_ingress_threat_model_prototype_substrate`
- `gate_h_integrated_native_adversarial_campaign`
- `gate_i_pq_hybrid_research_posture`
- `gate_j_v0.9.0_release_candidate_closure`

## Exit policy

- release-blocker findings: nonzero in all aggregates;
- high findings: visible non-clean status in dev profiles and nonzero in closure/release profiles unless explicitly accepted/deferred;
- medium findings: classified in report and not auto-fail unless a closure profile says so;
- informational findings: report only.

## G4 service/systemd/helper boundary

G4 may later add a local/private lifecycle-management substrate. It must start with docs, contract, and threat model. It must not imply public deployment readiness.

G4 must preserve:

- no automatic privilege escalation;
- no silent install;
- no public bind by default;
- explicit config and root reporting;
- explicit status/check/remove/refusal behavior;
- no destructive cleanup outside explicit roots.

## G5 public-ingress boundary

G5 may later add public-ingress threat-model or prototype-substrate work. Public ingress is default-disabled.

If a G5 surface exists, Gate H must attack it. G5 does not mean public deployment readiness, ingress safety, hostile-server safety, metadata privacy, or production security.

## Containers

Containers are completely deferred until late v0.9.x or v0.10.0-era planning. Gate G must not add Dockerfiles, compose files, container profiles, or container docs-as-readiness except as explicit deferment/nonclaim text.

## Nonclaims

This contract is not:

- production security;
- production E2EE;
- verified identity;
- trust promotion;
- secure enrollment;
- malicious-relay safety;
- metadata privacy;
- service readiness;
- systemd readiness;
- helper install readiness;
- public-ingress safety;
- public deployment readiness;
- container readiness;
- release/package mutation;
- external audit;
- external pen-test completion;
- PQ/hybrid security;
- Android readiness;
- CarbonStackOS implementation;
- TUI/public UX;
- `full-runtime-dev` promotion.
